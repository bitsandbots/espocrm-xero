Release

espocrm-xero is an open-source EspoCRM module that provides bidirectional sync between EspoCRM and Xero Accounting. It follows the EspoCRM extension pattern (custom/Espo/Modules/) and modifies zero core files — all logic is contained within the module directory.

What Syncs
EspoCRMXeroDirectionTrigger
AccountContact→ PushafterSave hook, Reconcile job
ContactContact→ PushafterSave hook, Reconcile job
Account / ContactContact updates← PullSyncFromXero nightly job
Invoice (custom)Invoice (ACCREC)→ PushafterSave hook, Reconcile job
Invoice.status → PaidPayment received← PullSyncFromXero nightly job
Design Principles
  • No core modifications — zero edits to EspoCRM core; 100% isolated in custom/
  • EspoCRM as CRM source of truth — Xero is authoritative only for payments
  • Last-modified-wins conflict resolution — ties go to EspoCRM
  • Hook loop guard — skipXeroSync save option prevents infinite re-entry
  • Graceful degradation — API failures are logged but never abort a CRM save
  • Stateless jobs — jobs use lastSyncAt from the Integration entity for watermarking

Push Flow (Real-Time via Hooks)

When any Account, Contact, or Invoice is saved in EspoCRM, an afterSave hook immediately pushes the change to Xero. The hook fires at priority order = 20 (after EspoCRM's own hooks).

User clicks Save ↓ EspoCRM ORM.saveEntity() ↓ Fire afterSave hooks (order 20) ↓ XeroSync::afterSave() ↓ Check skipXeroSync option → if set, return (loop guard) ↓ XeroService::upsertContact() / upsertInvoice() ↓ getAccessToken() → refresh if expiring within 30s ↓ HTTP POST to Xero API ↓ On success: write back xeroContactId / xeroInvoiceId → saveEntity(entity, ['skipXeroSync' => true]) ← prevents re-entry ↓ On failure: log warning at WARNING level → CRM save still completes (Xero failure is non-blocking)
Loop Guard: All internal saves after sync include 'skipXeroSync' => true in the save options. Hooks check this flag before executing, preventing infinite re-entry.
Invoice Prerequisite: Invoice sync requires the linked Account to have a xeroContactId already populated. Save the Account first if it is new. The nightly Reconcile job handles any invoices that fail this check.
Pull Flow (Nightly Background Jobs)

SyncFromXero — Daily Pull

Runs at 2:00 AM daily. Fetches all Xero contacts and payments updated since lastSyncAt. On first run, defaults to the past 7 days.

SyncFromXero.run() ↓ Read lastSyncAt from Integration entity (default: now − 7 days on first run) ↓ GET /Contacts?If-Modified-Since={lastSyncAt} ↓ For each Xero contact: → Find EspoCRM Account / Contact by xeroContactId → ConflictResolver: is Xero newer than xeroSyncedAt? → If yes: update name, email, phone → save(skipXeroSync=true) ↓ GET /Payments?where=Date>=DateTime({lastSyncAt}) ↓ For each payment: → Find EspoCRM Invoice by xeroInvoiceId → Set status=Paid, store xeroPaymentId + xeroPaymentDate → save(skipXeroSync=true) ↓ Write lastSyncAt = now() to Integration entity

ReconcileXero — Nightly Push

Runs at 2:15 AM daily (15 min after SyncFromXero). Pushes any EspoCRM records that Xero has not yet received. Processes a maximum of 25 records per run to stay within Xero's 60 requests/minute rate limit.

ReconcileXero.run() ↓ Query Accounts WHERE xeroContactId IS NULL (never synced) → upsertContact() for each (batch 25) ↓ Query Accounts WHERE xeroContactId IS NOT NULL → For each: if modifiedAt > xeroSyncedAt → upsertContact() ↓ Query Invoices WHERE status NOT IN (Paid, Voided) AND xeroInvoiceId IS NOT NULL → For each: if modifiedAt > xeroSyncedAt → upsertInvoice() ↓ Write lastSyncError (null on success, error list on failure)
Rate Limiting: Xero enforces 60 API requests/minute per organisation. The 25-record batch cap leaves headroom for push hooks firing in the same window. Large backlogs are processed across multiple nightly runs.
OAuth 2.0 Authorization Flow
1. Admin clicks "Connect to Xero" ↓ 2. POST /api/v1/XeroIntegration/initOAuth (admin-only) State: random = bin2hex(random_bytes(16)) Stored in Integration.oauthState Returns { state: "abc123..." } ↓ 3. Frontend builds authorization URL: https://login.xero.com/identity/connect/authorize ?client_id={CLIENT_ID} &response_type=code &scope=offline_access accounting.contacts accounting.invoices accounting.payments &redirect_uri={siteUrl}?entryPoint=XeroOauthCallback &state={STATE} ↓ 4. Frontend opens popup to authorization URL ↓ 5. User logs in and approves scopes in Xero ↓ 6. Xero redirects to ?entryPoint=XeroOauthCallback Params: code, state ↓ 7. XeroOauthCallback.run() → Validate state == Integration.oauthState (CSRF check) → POST https://identity.xero.com/connect/token grant_type=authorization_code, code, redirect_uri, client credentials → Store accessToken, refreshToken, accessTokenExpiresAt → GET https://api.xero.com/connections → Store tenantId (first connection) → Clear oauthState ↓ 8. Popup posts window.opener.postMessage({success:true}) ↓ 9. Popup closes; admin UI refreshes → shows Connected + tenantId

Token Refresh

Tokens refresh automatically inside XeroService::getAccessToken(). A 30-second safety margin triggers a proactive refresh before a request that might otherwise arrive at Xero with an expired token.

TokenLifetimeRefresh Trigger
Access token~30 minutesAutomatic — checked before every API call
Refresh token~60 daysManual reconnect required if expired
Conflict Resolution

Tools/ConflictResolver::resolve(?string $xeroLastUpdated, ?string $espoSyncedAt): string is a pure, stateless function. It compares timestamps and returns one of three constants.

ScenarioResultAction
Both timestamps nullWINNER_NONESkip — no data to compare
Only Xero timestamp knownWINNER_XEROPull Xero data into EspoCRM
Only EspoCRM timestamp knownWINNER_ESPOPush EspoCRM data to Xero
Both known; Xero is newerWINNER_XEROPull Xero data into EspoCRM
Both known; EspoCRM is newerWINNER_ESPOPush EspoCRM data to Xero
Timestamps exactly equalWINNER_ESPOEspoCRM wins (tie-break)
Design note: ConflictResolver has zero I/O dependencies (no DB, no network) making it trivially testable and safe to call at high frequency.

git clone https://github.com/coreconduit/espocrm-xero.git
cd espocrm-xero
scripts/install.sh --espo-path /path/to/espocrm

The install script:

  1. Validates that EspoCRM is installed at the target path
  2. Copies custom/Espo/Modules/Xero/ to the EspoCRM tree
  3. Copies client/custom/modules/xero/ to the EspoCRM tree
  4. Runs php command.php rebuild to register metadata and update the schema
  5. Runs php command.php clear-cache
  6. Prints post-install configuration steps

HTTPS / TLS Setup
Xero requirement: Xero's OAuth 2.0 server rejects any redirect URI that does not use HTTPS. The integration will not work over plain HTTP.

Development — mkcert

sudo apt-get install mkcert
sudo mkcert -key-file /etc/ssl/cake.local-key.pem \
            -cert-file /etc/ssl/cake.local.pem cake.local

nginx Configuration

server {
    listen 8080;
    server_name cake.local;
    return 301 https://$server_name:8443$request_uri;
}

server {
    listen 8443 ssl;
    server_name cake.local;
    root /path/to/espocrm;
    index index.php;

    ssl_certificate     /etc/ssl/cake.local.pem;
    ssl_certificate_key /etc/ssl/cake.local-key.pem;

    add_header Strict-Transport-Security "max-age=31536000" always;
    add_header X-Content-Type-Options "nosniff" always;

    location / { try_files $uri $uri/ /index.php?$query_string; }

    location ~ \.php$ {
        fastcgi_pass unix:/run/php/php8.3-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        include fastcgi_params;
    }

    location ~* ^/(data|custom|application|vendor)/ { deny all; }
    location ~ /\. { deny all; }
}

After updating nginx: sudo nginx -t && sudo systemctl reload nginx

Set EspoCRM site URL: Admin → Settings → Site URL → https://cake.local:8443

Xero App Configuration

1. Create a Xero Developer App

  1. Sign in at developer.xero.com → My Apps → New app
  2. Choose Web app as integration type
  3. Under Redirect URIs, add exactly:
    https://your-espocrm-domain.com?entryPoint=XeroOauthCallback
  4. Under Scopes, select: openid profile email offline_access accounting.contacts accounting.invoices accounting.payments accounting.reports.read
  5. Copy Client ID and Client Secret

2. Find Your Default Account Code

Xero requires every invoice line item to reference a chart-of-accounts code.
In Xero: Accounting → Chart of Accounts — note the Code column for your income account (e.g., 200 for Sales).

3. Configure in EspoCRM

  1. Go to Admin → Integrations → Xero
  2. Toggle Enabled to on
  3. Enter Client ID and Client Secret
  4. Enter Default Account Code (e.g., 200)
  5. Click Save
  6. Click Connect to Xero — authorize in the popup
  7. After the popup closes, verify tenantId and connectedAt are populated

OAuth Callback Entry Point

File: EntryPoints/XeroOauthCallback.php

URL: {siteUrl}?entryPoint=XeroOauthCallback

Authentication: NoAuth trait (unauthenticated — browser redirect from Xero)

Security checks performed on every callback:

  1. Validates state param is present and matches Integration.oauthState
  2. Rejects if Integration has no stored state token (replay attack guard)
  3. Exchanges code for tokens via POST identity.xero.com/connect/token
  4. Calls GET api.xero.com/connections to fetch tenant ID
  5. Clears oauthState from Integration on success

Troubleshooting
OAuth fails: "Invalid Redirect URI"

Cause: siteUrl doesn't match registered URI, or HTTPS cert is untrusted.

  1. Verify siteUrl in Admin → Settings is exactly https://cake.local:8443
  2. For mkcert (dev): visit the URL in your browser and accept the certificate warning
  3. Verify the exact redirect URI registered in developer.xero.com matches your siteUrl
"Xero integration is not enabled"

Cause: Integration is disabled, or connection was lost.

Go to Admin → Integrations → Xero, toggle Enabled, and reconnect.

Invoice sync fails: "no Xero Contact ID"

Cause: The linked Account has not been synced to Xero yet.

Save the Account record once to trigger the hook, or wait for the nightly Reconcile job. Then save the Invoice again.

Xero API rejects invoice: account code error

Cause: defaultAccountCode is not set or references a non-existent/archived account.

Set a valid account code in Admin → Integrations → Xero → Default Account Code. Use the Code column from Xero → Accounting → Chart of Accounts.

Token refresh failures / "No access token"

Cause: Refresh token expired (~60 days of inactivity).

Reconnect via Admin → Integrations → Xero → Connect to Xero.

Sync jobs not running

Cause: Cron is not configured or scheduled jobs are disabled.

  1. Check cron: sudo crontab -l | grep cron.php
  2. Test manually: php /path/to/espocrm/cron.php
  3. Verify jobs are enabled in Admin → Scheduled Jobs
  4. Check data/logs/espo.log for scheduler errors
Payments not marking invoices as Paid

Cause: Invoice was created in Xero directly, not pushed from EspoCRM — there is no matching xeroInvoiceId.

Only invoices originally pushed from EspoCRM (with a xeroInvoiceId) can be matched to Xero payments.

Gap Detail: Disconnect Endpoint (#1)

Once connected to Xero, there is no admin UI button to clear tokens and reconnect to a different organisation. Workaround: clear via CLI:

php command.php config:set --name=integration_data_Xero \
  --value='{"clientId":"...","clientSecret":"..."}'

Fix approach: Add deleteActionConnection() to the controller to null out accessToken, refreshToken, tenantId, and connectedAt. Add a Disconnect button to the admin view.
